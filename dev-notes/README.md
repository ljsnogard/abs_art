# dev-notes

这个文件夹用来存放开发过程中遇到的技术困难，以及记录技术决策的前因后果。

## 文件内容及规范

文件格式一律为 markdown 格式。

### 文件名规范

`[模块名]-[日期]`。其中日期时间格式为 `YYYYMMDD-hhmm`。

### 写作要求

- **以因果链为主**：写清楚「为什么这么做」，而不只是「做了什么」；
- **证据优先于推断**：涉及运行时行为的结论必须附可复现的实测命令与原始结果，
  不能只凭读源码推断；
- **及时清理过时内容**：技术决策改变后，与最终决策无关的旧讨论应当删掉，
  日志本身有版本记录，不必担心内容遗失。
